# Wattlyst build plan for Claude Code

Read this file, CLAUDE.md and PROGRESS.md at the start of EVERY session. Work one phase at a time,
one page per PR. Never start the next phase until the current gate is green.

## Non-negotiable rules (copy into the repo's CLAUDE.md)
1. Math lives only in `engine/` as pure functions (no DOM, no WordPress). UI code calls the engine; it never re-implements a formula.
2. Every engine function has unit tests generated from `specs/calculator-test-cases.json`. Change a formula = change formulas.md + tests in the same PR. Never delete or loosen a test to get green.
3. Constants that can change (tariff, buyback, prices, sun hours, appliance watts, cable ampacity) live in `data/*.json` with `source`, `checked` date. No magic numbers in JS.
4. A page is done only when: tests green, Engineer Reviewer PASS (specs/engineer-reviewer.md), content checklist PASS (below), Lighthouse mobile >= 95 Performance/SEO/Accessibility/Best Practices.
5. Every page's primary keyword, URL, title and meta come from `keyword-map.csv`. Don't invent URLs; one intent = one URL.
6. Update PROGRESS.md (page id, status, PR link, date) at the end of each session.
7. Results never show NaN, Infinity, negative or blank; invalid input shows a clear message.
8. Every page in every phase follows `specs/seo-rules.md` (single source of truth, titles/meta, on-page, technical SEO, AEO, GEO/LLM, Google policies, AdSense). Numbers in content, examples, FAQ, meta and schema are generated by the engine, never typed.

## Repo layout (repo root IS the plugin; Hostinger deploys `main` into wp-content/plugins/wattlyst-tools)
```
wattlyst/                 = plugin wattlyst-tools
  wattlyst-tools.php      plugin bootstrap
  CLAUDE.md  PROGRESS.md  README.md  package.json  .htaccess (blocks .git, specs, tests, md/csv/json-config over the web)
  specs/      build-plan.md, formulas.md, calculator-test-cases.json, engineer-reviewer.md, seo-rules.md, keyword-map.csv, serp-analysis.csv
  data/       defaults.json, tariff-pk-2026.json, cities-pk.json; later appliances.json, cable-ampacity.json, solar-prices.json, generator-fuel.json, inverter-codes.json (from manufacturer manuals, with source link per code)
  engine/     core.js conversions.js battery.js sizing.js solar.js bill.js load.js wiring.js messages.js index.js  (ES modules, pure)
  tests/      node:test (no dependencies): engine.test.js (every spec case), guardrails.test.js (NaN/Infinity/negative fuzz), messages.test.js, keyword-map.test.js (SEO rules)
  includes/   PHP: one block/shortcode per tool, enqueues only that tool's JS, renders default result server-side, outputs schema
  assets/js/  one small vanilla JS file per tool (imports engine/)
  assets/css/ tool styles (theme = GeneratePress from wordpress.org; child theme only if needed)
  .github/workflows/ci.yml  npm test on every PR (Lighthouse CI added in Phase 2)
```
Canonical copies of specs/ and data/ are in the repo. The project folder copy is synced after every change.

## Content checklist (per page)
- [ ] H1 = primary keyword; title/meta from keyword-map.csv
- [ ] One-line direct answer above the fold; tool usable on 360px screen
- [ ] "How this result was calculated" uses the user's numbers
- [ ] Formula section matches formulas.md; 3-5 worked examples recomputed by engine
- [ ] Reference table generated by engine (not typed by hand)
- [ ] Common mistakes + safety note where relevant
- [ ] 4-8 internal links incl. pillar + chain Next step; 3+ pages link to it
- [ ] FAQ 5-8 real questions; author + reviewer box; last reviewed date; sources
- [ ] Data pages: source link + checked date <= 35 days
- [ ] Direct answer 40-60 words + "Key facts" block of quotable sentences (AEO/GEO, seo-rules.md 5-6)
- [ ] Schema valid in Rich Results Test and matches visible content; canonical correct; page in sitemap + llms.txt
- [ ] No ad near inputs/Calculate button; no claim the page cannot prove (seo-rules.md 7-9)
