The next phase's thread reads that note first instead of the whole codebase.

## Non-negotiable rules (copy into the repo's CLAUDE.md)
1. Math lives only in `engine/` as pure functions (no DOM, no WordPress). UI code calls the engine; it never re-implements a formula.
2. Every engine function has unit tests generated from `specs/calculator-test-cases.json`. Change a formula = change formulas.md + tests in the same PR. Never delete or loosen a test to get green.
3. Constants that can change (tariff, buyback, prices, sun hours, appliance watts, cable ampacity) live in `data/*.json` with `source`, `checked` date. No magic numbers in JS.
4. A page is done only when: tests green, Engineer Reviewer PASS (specs/engineer-reviewer.md), content checklist PASS (below), Lighthouse mobile >= 95 Performance/SEO/Accessibility/Best Practices.
5. Every page's primary keyword, URL, title and meta come from `keyword-map.csv`. Don't invent URLs; one intent = one URL.
6. Update PROGRESS.md (page id, status, PR link, date) at the end of each session.
7. Results never show NaN, Infinity, negative or blank; invalid input shows a clear message.
8. Every page in every phase follows `specs/seo-rules.md` (single source of truth, titles/meta, on-page, technical SEO, AEO, GEO/LLM, Google policies, AdSense). Numbers in content, examples, FAQ, meta and schema are generated by the engine, never typed.

## Design rules (owner, 13 Oct 2026; every phase, every page)
The site is a problem solver: a visitor must see at once where everything is and reach their answer without wandering.
- Clean, professional, easy to understand: one accent colour, consistent components (same field, button, result card, table and FAQ look on every page), plenty of white space, no clutter.
- Above the fold on a 360 px phone: breadcrumb, H1, one-sentence answer, the calculator with defaults pre-filled; the result appears right under the Calculate button.
- Navigation by task, not by jargon: header menu = the silo hubs (Battery & UPS, Solar, Generator, Bill, Wiring, Converters, Home load), each hub lists its tools with a one-line "use this when"; homepage = "What do you want to do?" task cards (Phase 4 planner). Breadcrumb on every page.
- After every result: a clear "Next step" link to the next tool in the chain, plus 3+ related tools. Never a dead end.
- Plain words and short sentences; every field shows its unit and a hint; advanced settings are folded away; errors say exactly what to fix.
- No pop-ups, interstitials, carousels or auto-playing media; no sidebar on tool pages; ads never inside or next to the tool (seo-rules.md 8).
- Accessible and mobile first (see Phase 2 accessibility item): 44 px touch targets, visible focus, AA contrast.

## Phase 2: Templates, trust and data
- Block/shortcode framework, server-side default result, URL-param state (?load=..), canonical clean URL.
- Tool page template (order in the strategy doc), pillar template, appliance template, guide template.
- Schema: WebApplication, BreadcrumbList, Article + Person (reviewer), Organization + WebSite (seo-rules.md section 4).
- robots.txt (AI crawlers allowed), XML sitemap, /llms.txt generated from keyword-map.csv, Bing Webmaster Tools + IndexNow, canonical for ?load= URLs.
- Trust pages: About, Methodology, Editorial policy, Contact, Privacy, Terms, Disclaimer.
- data/appliances.json: 60+ appliances (running W, starting W, PK brand examples, source).
- Ad slot partials with reserved height (not used until AdSense approval); privacy policy with Google cookie disclosure, certified CMP, ads.txt ready (seo-rules.md section 8).
- Brand images (owner, 13 Oct 2026): logo (SVG + 512 px PNG for Organization schema), favicon (ICO + 32/192/512 PNG), Apple touch icon 180 px, default Open Graph share image 1200x630 and Twitter card image (summary_large_image). Open Graph + Twitter meta on every page.
- Freshness: every page shows "Last reviewed"; data pages show the "Last checked" date of the data/*.json they use, so a data refresh updates the page date automatically.
- E-E-A-T slots: PEC engineer reviewer fields in data/site.json (name, credential, PEC registration no., profile link), shown in the author box and Article.reviewedBy only once `reviewer.status` = "signed_off". Brand social profiles (YouTube, Facebook, X, LinkedIn page) go in `organization_same_as` as soon as they exist.
- Speed stack (owner, hPanel/WordPress): LiteSpeed Cache plugin (page cache, CSS/JS minify, no JS delay on tool pages), Cloudflare CDN (proxy, Brotli, cache static assets), images served as WebP/AVIF.
- Search engines on launch day (owner): Google Search Console + Bing Webmaster Tools (import from GSC), submit /wp-sitemap.xml (or the Rank Math sitemap) in both; IndexNow pings are sent by the plugin on every publish/update.
- No staging (owner decision, 13 Oct 2026): work happens on the live site. Every change is checked first on a local WordPress + GeneratePress copy (`tools/wp-test-site.sh`) and must pass `npm test` + the CI Lighthouse job before it is merged into `main` (live).
- ads.txt (owner, 13 Oct 2026): served at /ads.txt by the plugin from data/site.json `ads.adsense_pub_id` (`google.com, pub-..., DIRECT, f08c47fec0942fa0`). Empty until AdSense gives the publisher id; then set the id and check https://wattlyst.com/ads.txt before applying.
- Accessibility (owner, 13 Oct 2026), WCAG 2.2 AA on every page: every input has a visible label and unit; hints and error messages are tied to their field (aria-describedby, aria-invalid); errors are announced (role=alert) and focus moves to the wrong field; results update in an aria-live region; the whole calculator works with keyboard only (Tab, Enter, arrow keys in selects) with a visible focus ring; touch targets >= 44 px; colour contrast >= 4.5:1; tables have header cells; no information by colour alone. Checked by Lighthouse accessibility >= 95 plus a manual keyboard + screen-reader (TalkBack/VoiceOver) pass on each template.
Gate: template page scores >= 95 on Lighthouse mobile in all 4; no CLS from slots; trust pages live.

## Content checklist (per page)
- [ ] H1 = primary keyword; title/meta from keyword-map.csv
- [ ] One-line direct answer above the fold; tool usable on 360px screen
- [ ] "How this result was calculated" uses the user's numbers
- [ ] Formula section matches formulas.md; 3-5 worked examples recomputed by engine
- [ ] Reference table generated by engine (not typed by hand)
- [ ] Common mistakes + safety note where relevant
- [ ] 4-8 internal links incl. pillar + chain Next step; 3+ pages link to it
- [ ] FAQ 5-8 real questions; author + reviewer box; last reviewed date; sources
- [ ] Data pages: source link + checked date <= 35 days
- [ ] Direct answer 40-60 words + "Key facts" block of quotable sentences (AEO/GEO, seo-rules.md 5-6)
- [ ] Schema valid in Rich Results Test and matches visible content; canonical correct; page in sitemap + llms.txt
- [ ] No ad near inputs/Calculate button; no claim the page cannot prove (seo-rules.md 7-9)
