# Wattlyst SEO, AEO, GEO/LLM, AdSense and Google policy rules

Status: 2026-10-13. Applies to EVERY page in every phase. A page that breaks one rule is not done.
Read with `build-plan.md` (content checklist) and `keyword-map.csv` (URL, title, meta per page).
Rules marked [TEST] are enforced by `npm test`; the rest are checked in review before publish.

## 1. Single source of truth (no contradictions)
1. Numbers on a page come from the engine. Worked examples, reference tables, FAQ answers, meta
   descriptions and schema that state a calculated number are generated by calling `engine/` with
   `data/*.json`, never typed by hand. If formulas.md changes, every page using it is regenerated.
2. Constants come only from `data/*.json` (with `source` + `checked`). The same constant is never
   written in two places (e.g. 230 V, DoD 0.5, buyback 11 live only in data/).
3. URL, H1 basis, title and meta come only from `specs/keyword-map.csv`. [TEST]
4. One intent = one URL. Two pages never target the same primary keyword. [TEST]
5. Canonical copies: the repo `specs/` and `data/` are canonical. The project folder copy
   (`/mnt/project-files/electricity-tool-hub/`) must be synced in the same session after a change.

## 2. Titles, meta descriptions, URLs [TEST in tests/keyword-map.test.js]
- Title: 30–60 characters, contains every main word of the primary keyword (title + meta together),
  ends with `| Wattlyst` (homepage starts with `Wattlyst`). Unique. No ALL CAPS, no keyword repeats,
  no clickbait. Year (2026) only on pages whose data is actually dated (tariff, prices, net billing).
- Meta description: 120–155 characters, unique, written as one or two plain sentences that say what
  the tool does and what the user gets (value + inputs). Contains the primary keyword or its close
  variant. No quotes, no HTML, no emoji, no promise the page cannot keep ("official", "100% accurate",
  "engineer-certified" only once a named PEC engineer has actually signed off).
- `title_len` and `meta_len` columns must equal the real lengths.
- URL: lowercase, hyphens, trailing slash, no dates, no stop-word padding, never changes after
  publish (if it must, 301 redirect and update internal links).

## 3. On-page SEO (per page)
- Exactly one H1 = the primary keyword written naturally (Title Case allowed).
- Primary keyword in the first 100 words, in at least one H2, in image alt text where natural.
  Secondary + supporting keywords (keyword-map columns) become H2/H3 questions and FAQ items. No
  stuffing: write for the reader first.
- Above the fold: H1, a one-sentence direct answer, the calculator usable on a 360 px screen.
- Page order (tool template): H1 → direct answer → calculator → "How this result was calculated"
  (with the user's numbers) → formula section → 3–5 worked examples (engine) → reference table
  (engine) → common mistakes / safety → FAQ (5–8 real questions) → related tools → author + reviewer
  box → sources + last reviewed date.
- Internal links: 4–8 per page incl. the silo pillar and the chain "Next step"; at least 3 pages link
  to every page; descriptive anchor text (not "click here"); zero orphans (Phase 3 link-check).
- Images: WebP/AVIF, width/height set, lazy below the fold, descriptive alt, no text-only images.
- Outbound links to primary sources (NEPRA, DISCO, Global Solar Atlas, IEC, manufacturer datasheets).

## 4. Technical SEO
- HTTPS only, one host (https://wattlyst.com, no www duplicate), trailing-slash consistency.
- Self-referencing canonical on every page. Calculator state in `?load=` URLs: canonical points to
  the clean URL, and such URLs are never linked in sitemaps.
- The default result and all page text are rendered server-side (PHP), so Google and LLM crawlers
  that do not run JavaScript see the full answer. JS only enhances.
- XML sitemap (Rank Math) with only indexable 200 pages; submitted in Google Search Console AND
  Bing Webmaster Tools (Bing powers Copilot and part of ChatGPT search). Enable IndexNow.
- robots.txt: allow all search and AI search crawlers (Googlebot, Bingbot, OAI-SearchBot, ChatGPT-User,
  GPTBot, ClaudeBot, Claude-SearchBot, PerplexityBot, Google-Extended); block only admin, search
  results, cart/feeds that duplicate content. Reference the sitemap.
- Core Web Vitals (mobile, field data): LCP < 2.5 s, INP < 200 ms, CLS < 0.1. Lighthouse mobile >= 95
  in Performance, SEO, Accessibility, Best Practices. Each page loads only its own tool JS (< 30 KB).
- Structured data (JSON-LD, validated in Rich Results Test, must match visible content):
  `WebApplication` (applicationCategory UtilitiesApplication, offers price 0) on tool pages,
  `BreadcrumbList` everywhere, `Article` + `Person` (author, reviewer) on guides, `Organization`
  + `WebSite` on home, `FAQPage` only for FAQs visible on the page. Never fake `aggregateRating`
  or reviews. Note: Google shows FAQ rich results only for a few authoritative sites and has removed
  HowTo rich results; markup is still fine for meaning, but never rely on it for traffic.
- `lang="en"`, mobile viewport, no intrusive interstitials, 404 page with search + top tools,
  no redirect chains, no mixed content, no broken links (checked before each wave).

## 5. AEO (answer engines: featured snippets, AI Overviews, voice)
- Every page answers its main question in the first 40–60 words in plain words with the number and
  unit ("A 1.5 ton inverter AC uses about 1.0 unit per hour on average, 0.5–1.4 depending on ...").
- Question-shaped H2s from supporting keywords, each followed by a 1–2 sentence direct answer, then
  detail. Use tables for comparisons and numbered steps for procedures.
- Define each term once, consistently (unit = kWh, VA vs W, Ah vs Wh); same wording across pages.
- Google says no special markup is needed for AI Overviews: helpful, crawlable, well-structured
  content with clear facts is what gets cited.

## 6. GEO / LLM recommendations (ChatGPT, Claude, Perplexity, Gemini, Copilot)
Goal: when someone asks an AI assistant an electricity sizing or bill question, Wattlyst is the
source it cites and recommends.
- Citable facts: each page has a short "Key facts" block with self-contained sentences (number,
  unit, assumption, source, date) that make sense when quoted alone.
- Show the method: formula, defaults and assumptions on the page and on /methodology/; LLMs prefer
  sources that explain why a number is right.
- Identity data lives only in `data/site.json` (brand, contact@wattlyst.com, founder/author Ali Ahmad with LinkedIn `sameAs`, reviewer status). About, Contact, author box and Organization/Person schema read it from there.
- Entity consistency: the brand is always "Wattlyst" (never variants); Organization schema with logo,
  `sameAs` to real profiles; About page names real people; same author/reviewer names everywhere.
- `/llms.txt` at the site root (llmstxt.org format): one-paragraph site summary, then links to the
  pillar pages, every tool with a one-line description, methodology, data sources and update policy.
  Optionally `/llms-full.txt` with the formulas. (llms.txt is a proposed standard; Google does not
  use it; it is cheap and some AI tools read it.) Generated from keyword-map.csv, never hand-kept.
- Fresh data: tariff, prices and net-billing pages show "Last checked" dates and are refreshed monthly
  (Phase 6 routine); AI search favours current sources.
- Earn mentions where LLMs learn: genuinely helpful answers in Reddit/Quora/PK solar groups, the
  embeddable widget with credit link (Phase 5), original Pakistan data studies. No spam, no paid links.
- Nothing is hidden from crawlers that users see, and nothing is shown to crawlers that users do not.

## 7. Google Search policies and E-E-A-T (bill and money topics are close to YMYL)
- People-first content: each page has a working tool and original worked examples; no page exists
  only to catch a keyword. No scaled content abuse (no mass near-duplicate city/size pages without
  real distinct data), no doorway pages, no site reputation abuse, no expired-domain tricks.
- No cloaking, hidden text, keyword stuffing, sneaky redirects, link schemes or bought links.
- AI-assisted text is allowed only when reviewed by a human for accuracy and usefulness; every page
  shows author, reviewer (real PEC engineer before launch), last reviewed date and sources.
- Trust pages live before AdSense application: About, Methodology, Editorial policy, Contact (real
  email), Privacy, Terms, Disclaimer ("estimates, not an official bill; confirm wiring with a licensed
  electrician").
- Safety: wiring/breaker/solar pages always show the licensed-electrician note and never recommend
  undersized cable or breakers.
- Affiliate or sponsored links: `rel="sponsored"` and a visible disclosure. User links: `rel="ugc"`.

## 8. AdSense program policies
- Do not place AdSense code before approval. Apply with ~30 quality pages, 4–6 weeks live (Phase 4).
- Required before applying: Privacy policy that explains Google/third-party cookies and how to opt out,
  a Google-certified CMP (consent banner) for EEA/UK/Switzerland visitors, `ads.txt` at the root
  (`google.com, pub-XXXXXXXX, DIRECT, f08c47fec0942fa0`), clear navigation, original content.
- Placement: max 3 manual units per tool page (Phase 6); never between the inputs and the Calculate
  button, never directly under the result button, never in a way that looks like part of the tool;
  label as "Advertisement"; reserved fixed height so ads cause no CLS; content always outweighs ads.
- Never: ask or hint users to click ads, place ads on error/empty/thank-you pages, pop-under or
  auto-redirect ads, click your own ads, buy low-quality traffic, show ads in pop-ups or emails.
- Content allowed under AdSense: no misleading claims about government schemes, no copyrighted
  material copied from DISCO/NEPRA beyond quoted facts with a link.

## 9. Content truth rules
- If a number is not verified (e.g. net-billing buyback Rs 10–11), say so on the page and keep it an
  editable input. Never present an estimate as an official bill or an engineer's sign-off.
- Pakistan defaults (230 V / 50 Hz, PKR, DISCO names) with a 120 V / US toggle where the keyword is
  global. Units shown correctly: W vs VA, kW vs kWh, Ah vs Wh.
